# Documentation Sync To Codebase State

Goal: make README/AGENTS/docs match the real codebase with minimum effort.

Target:

$ARGUMENTS

If no target is provided, analyze the whole repository.

## Required Skill

Before creating diagrams, invoke `skill uml`.

All diagrams MUST use PlantUML:

- Fence: ` ```plantuml ` or ` ```puml `
- Start: `@startuml`
- End: `@enduml`
- Never use Mermaid

## Principle

Do not make documentation bigger. Make it closer to code.

Prefer:

1. README as entrypoint and index only.
2. AGENTS.md as durable agent rules and codemap only.
3. Code, config, scripts, and tests as the single source of truth.
4. PlantUML diagrams over long architecture prose.
5. Deleting stale prose over rewriting it.
6. Source anchors under every diagram as Markdown after the closing code fence:
   ```md
   **Source anchors:**
   - `path/to/source` — what it anchors
   ```

## Step 1: Launch 6 Fast Audit Agents In Parallel

Launch ALL agents in ONE Task batch using `@ explore`. Use the flash/small model subagent.

### Agent 1: Docs Reality Check

Audit README, AGENTS, docs, CODEBASE, command docs.

For each claim classify:

- true
- stale
- partially stale
- unverifiable prose
- should move into code/config/test

Return exact file paths, stale claims, and evidence from code.

### Agent 2: Entrypoint Truth

Find real entrypoints:

- Makefiles
- run_scripts
- Dockerfiles
- docker-compose.yml
- launch files
- package.xml / CMakeLists.txt / setup.py / pyproject.toml

Return canonical commands and runtime structure.

### Agent 3: Architecture Truth

Infer architecture from code/config only.

Produce PlantUML diagrams:

- Component diagram — modules, ROS nodes, packages
- Deployment diagram — containers, hosts, hardware
- Data-flow diagram — ROS topics, sockets, IPC
- State machine diagram — mode/lifecycle logic from source

Every diagram MUST include source anchors below it as Markdown (after the closing code fence, NOT as PlantUML comments inside the fence).

### Agent 4: Code-Embedded Docs Opportunities

Find documentation that should move into:

- config comments
- launch file parameters
- script usage/help text
- Doxygen for physical/math semantics
- tests or validation schemas

Return minimal move/delete recommendations.

### Agent 5: AGENTS.md Contract Audit

Audit ALL AGENTS.md files.

Keep only durable rules:

- canonical workspace paths
- naming conventions
- forbidden assumptions
- safety rules
- build/run constraints
- agent behavior constraints

Remove volatile architecture, topic lists, and duplicated command details.

### Agent 6: Final Doc Shape

Propose the final minimal doc layout:

- `README.md`: short overview + command index + links
- `AGENTS.md`: durable rules only
- `CODEBASE.md`: generated snapshot, explicitly disposable
- `docs/architecture.md`: PlantUML diagrams + source anchors, if scope justifies it
- code/config/tests: local truth for everything else

Return edit plan with delete/shorten/move candidates.

## Step 2: Synthesize Staleness Map

```md
## Must Fix
[file:line] stale claim -> evidence -> action

## Move Into Code
[file:line] doc claim -> target code/config/test location

## Delete Or Shorten
[file:line] reason

## Keep
[file] durable reason

## UML Needed
[diagram type] -> source files -> target doc
```

## Step 3: Apply Minimal Edits

Only edit after the staleness map is reviewed.

Editing rules:

- Prefer deletion over rewrite.
- Prefer links to source files over duplicated command blocks.
- Prefer PlantUML diagrams over architecture prose. Invoke `skill uml` before drawing.
- Keep README short (under ~200 lines unless scope justifies more).
- Keep AGENTS.md focused on rules that affect agent behavior.
- Mark generated snapshots with `> Auto-generated by /doc-sync <date>`.
- If a claim cannot be verified from code, remove it or mark it as assumption.

## Step 4: Verification

Run only cheap checks:

- markdown formatting if configured
- PlantUML fence syntax check
- local link check if practical
- do NOT run build/test unless docs changed commands or scripts
